## What's NOT Ready (and blocks the LinkedIn campaign)

### 1. Graduate Talent Application Portal — DOES NOT EXIST

This is the #1 blocker. Lucy cannot post on LinkedIn saying "register on our portal" because there is no portal. No `/apply`, no `/talent`, no application form, no applicant database table, no document upload flow, no admin review interface.

**What needs to be built:**

| Component | Where | Storage |
|---|---|---|
| Public landing page | `/talent` or `/training/apply` | — |
| Multi-step application form | `/talent/apply` | Supabase `talent_applications` table |
| Document upload (degree cert, NYSC cert, employment letter) | Same form | Supabase Storage `aprn-documents` bucket |
| Application confirmation/status page | `/talent/status` | Supabase |
| Admin review dashboard | `/admin/talent` | Supabase |
| Email notifications (application received, status update) | API routes | Resend |

**Supabase table: `talent_applications`**

```
id               uuid PK default gen_random_uuid()
full_name        text NOT NULL
email            text NOT NULL
phone            text NOT NULL
university       text NOT NULL
discipline       text NOT NULL  -- engineering discipline
graduation_year  int NOT NULL   -- 2021–2026
degree_class     text NOT NULL DEFAULT 'first_class'
currently_employed boolean DEFAULT false
employer         text
-- document paths in aprn-documents bucket
degree_cert_path text NOT NULL
nysc_cert_path   text NOT NULL
employment_letter_path text     -- conditional
-- motivation answers
why_pipelines    text NOT NULL
why_pipelines_matter text NOT NULL
why_aprn         text NOT NULL
contribution_to_africa text NOT NULL
-- process
status           text DEFAULT 'submitted'  -- submitted | under_review | shortlisted | accepted | rejected
reviewer_notes   text
reviewed_by      text
submitted_at     timestamptz DEFAULT now()
reviewed_at      timestamptz
```

**This is roughly 3–4 sessions of work:**
- Session 1: Migration + API routes + Zod validation
- Session 2: Public landing page + multi-step form
- Session 3: Admin review dashboard
- Session 4: Email notifications + polish + testing

### 2. Training Page — Needs Rewrite for Talent Focus

The current `/training` page is a generic training catalogue. It lists tracks (Entry-Level Fundamentals, Professional Certification, Pipeline Integrity, etc.) and pulls from the `trainingProgram` Sanity schema.

For the LinkedIn campaign, this page needs a **Talent Initiative hero section** at the top — or the talent portal should be its own route (`/talent`) with `/training` linking to it.

My recommendation: **Keep `/training` as is, build `/talent` as the new dedicated route.** The training page serves the broader "what APRN offers" purpose. The talent portal is a specific campaign with specific eligibility requirements and an application flow.

### 3. Events — No Dynamic Route

`/events` has static pages (`/events/apc-2025`, `/events/apls-morocco-2026`) but no `/events/[slug]` dynamic route. If Lucy shares an event on LinkedIn and the slug doesn't match a hardcoded page, it 404s.

Not a launch blocker for the talent campaign, but will bite the moment she promotes an event.

### 4. Programs & Certification — Empty

`/programs` and `/certification` both have `page.tsx` files but are likely stubs. If navigation links to them, a LinkedIn visitor who explores will hit thin pages.

**Fix:** Either flesh them out or remove them from the nav until they're ready. I'd remove them for now.

## Site Corrections Needed Before LinkedIn Promotion

### Navigation
- **Remove `/programs` and `/certification` from nav** if they're stubs. A thin page hurts credibility more than a missing link.
- **Add `/talent` (or whatever the talent portal route is) to nav** once it's built. Make it prominent — this is the CTA Lucy will drive people toward.

### Content
- **Homepage:** Should reference the talent initiative in the hero or in a banner. When someone arrives from LinkedIn, they need to see the connection immediately. A "Now Accepting Applications" banner or section linking to `/talent`.
- **Training page:** Needs a prominent link/banner to the talent portal.

### Technical
- **Mobile responsiveness:** The PLAN.md lists 10+ mobile/accessibility issues. For LinkedIn traffic, mobile is 60–70% of visitors. Needs at least a quick pass on the most visited pages (homepage, about, and whatever the talent portal is).
- **OG images / metadata:** The talent portal page needs strong Open Graph metadata for LinkedIn previews. Title, description, and an OG image that communicates the programme. This matters — it's what people see before they click.

## My Assessment

The site has strong bones. The design language is distinctive — dark, angular, authoritative. The intelligence modules, research hub, and admin tooling are well above average for a membership platform at this stage. The Sanity + Supabase architecture is clean and the separation of concerns is correct.

But the gap between "site that exists" and "site that converts LinkedIn traffic into applicants" is significant. The talent portal is not a cosmetic addition — it's the primary product Lucy needs right now. Everything she described in that call (registration, eligibility screening, document collection, selection process) is new surface area.

The good news: the existing infrastructure (Supabase storage, auth, admin patterns, Zod validation, Resend) is all in place. The talent portal is a composition of patterns we've already built. The hardest part is the multi-step form UX and making the landing page compelling enough to convert a LinkedIn visitor who has never heard of APRN.

**Timeline estimate:** If we start now and focus exclusively on the talent portal, Phases 1–2 are 5–6 focused sessions. Phase 1 alone (the minimum for Lucy to post on LinkedIn) is 3–4 sessions.

## Decision: Route Structure

Two options:

**Option A: `/talent` (recommended)**
- `/talent` — landing page
- `/talent/apply` — application form
- `/talent/status` — check application status
- Clean, memorable URL for LinkedIn posts

**Option B: `/training/talent`**
- Nested under training
- Keeps training as the parent concept
- Less clean for LinkedIn sharing

I recommend Option A. Lucy will type this URL in LinkedIn posts. `/talent` is shorter and clearer than `/training/talent`.
